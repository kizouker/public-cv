What I Built & Learned

Across four public open-source repos (Holdmate, swedish-jobs-mcp, hrv-service, paula-lib), two hackathons (Meta Global AI Hackathon 2026, Kiroween 2026), FOI Crate-CTF 2026, multi-agent coordinator pipelines and a published Python engineering standard, six lessons stood out:

  • Specs matter more with AI, not less. Without concrete, observable acceptance criteria (EARS, OpenSpec, Gherkin), an agent produces fast, plausible-looking drift.
  • Separate building from verifying. Pairing a builder/coordinator agent with an independent verifier—backed by RED → GREEN → REFACTOR, ruff, ty and coverage gates—catches silent shortcuts. A passing test is evidence, not proof.
  • Git isolation unlocks real parallelism. Running agents in separate git worktrees and branch-only unattended sessions lets multiple tracks move forward without merge chaos or touching main.
  • Hard-code human-in-the-loop boundaries. External side effects—sending emails, submitting applications, touching live public phone lines or pushing/merging—must always stop for an explicit human yes.
  • Treat external text as untrusted data. Building an MCP server over public job ads made prompt injection and context-window flooding concrete design concerns: cap page sizes, expose minimal surface area and keep stdio servers local.
  • Model-agnostic standards outlive prompts. Keeping engineering rules in plain Markdown standards instead of model-specific prompts makes the same workflow portable across Claude, Gemini, OpenAI, Meta and local Ollama models.

Questions I Asked Myself — and My Answers

How do you verify systems that include non-deterministic LLM steps?

Surround the model with deterministic boundaries: strict JSON/schema validation, deterministic simulators (like Holdmate's 43-line finite-state practice robot), automated pytest suites and an explicit verifier step against written acceptance criteria.

Where does a new rule belong: in a prompt, a skill, a repo standard or memory?

Project-wide invariants belong in versioned repo standards (like Code standards); repeatable multi-step workflows belong in reusable SKILL.md skills; one-off goals stay in the task prompt. I codified this decision tree in a prompt-router skill.

How do you let agents work autonomously (overnight or in parallel) without losing control?

Constrained blast radius: dedicated feature branches or git worktrees, zero push/merge/send permissions, a coordinator + verifier split, and a structured review-tree walkthrough so every branch and decision can be audited before merging.

How do you train a voice agent against a public-agency phone robot without spamming the real line?

Simulator-first engineering: record and transcribe real calls into a local finite-state practice robot so BFS exploration and LLM intent normalisation run safely offline. On real calls, the human always handles BankID and takes over when a person answers.

How should AI assist creative and technical work without turning into a black box?

“Creative co-pilot, not a jukebox” (paula-lib): expose structured tools over MCP so the agent writes editable tracker patterns back into the grid rather than generating opaque flat audio.

How do you keep an MCP server safe and useful for different AI clients?

Run locally over stdio with no open network port, enforce paging (next_offset, max 25 items per call) so responses never flood the context window, configure timeouts and URLs via environment variables, and treat fetched third-party text as untrusted against prompt injection.
